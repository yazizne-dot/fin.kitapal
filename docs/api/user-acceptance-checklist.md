# Проверка PostgreSQL-версии пользователем

Приложение запускается двумя процессами из корня проекта: `npm run api:local` и `npm run dev` в разных терминалах. Откройте адрес, который напечатает Next.js (обычно `http://127.0.0.1:3000`). Локальные `.env.backend.local` и `.env.local` уже настроены для этой установки. Пароли в переписку не отправляйте.

Проверьте вход под своей учётной записью. Для существующих пользователей, включая администратора, первый вход требует смены пароля; затем смена повторяется каждые 30 дней. Новый пароль должен содержать не менее 15 символов. Проверьте, что после смены открывается ваша рабочая область, а выход завершает сессию.

Под учётной записью с доступом к консолидированному отчёту откройте отчёт о прибылях и убытках за август 2026 года. Отчёт показывает исходные цифры и предупреждения о недостающем показателе дивидендов и несходстве с отдельно сохранённым итогом с начала года. Переключите «Месяц / С начала года» и убедитесь, что предупреждения остаются понятными. Не считайте пустую нераспределённую прибыль нулём. Пользователь, ограниченный одной организацией, не должен видеть консолидированные исторические цифры без отдельного разрешения.

В редакторе отчётных чисел можно изменить отдельную цифру с причиной, затем проверить пересчитанную прибыль в P&L. Это представление отчёта: исходные документы, финансовые события и движения денег должны остаться прежними. Для проверки на своих данных используйте согласованную тестовую цифру и при необходимости сбросьте корректировку в том же редакторе; история изменений сохранится.

В режиме реестра проверьте операции, бюджет, план платежей, импорт CSV и закрытие/открытие периода только в допустимом для ваших данных периоде. В тестовой базе эти формы прошли браузерный сценарий. В настоящей `fin` наличные и банковские операции пока нельзя вводить: у трёх организаций нет подтверждённых денежных счетов. Не создавайте фиктивные счета ради проверки.

Баланс и ДДС остаются частичными: нет подтверждённых входящих остатков; у импортированных движений денег отсутствуют необходимые привязки к организациям и/или счетам. Не используйте эти экраны как сверенный итог, пока исходные измерения и остатки не будут восстановлены и проверены. Старые операции также не всегда содержат полные реквизиты документа и не доступны для исправления по исходному ID.

Если заметите ошибку, сообщите роль пользователя, страницу, выбранный период, действие и видимый текст ошибки. Пароли, токены и реквизиты счетов присылать не нужно.
