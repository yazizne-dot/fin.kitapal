# Приложение подключено к удалённой fin

Проверено 27.10.2026: соединение через существующий SSH-туннель `127.0.0.1:15433`, база `fin`, роль `qarzhy_app`. TLS использует закреплённый сертификат сервера с включённой проверкой цепочки. Пароль и строки подключения в этот документ не включены.

Роль разрешает LOGIN, но не имеет SUPERUSER/CREATEDB/CREATEROLE/BYPASSRLS. Проверены CONNECT, USAGE схемы, INSERT/UPDATE sessions и INSERT audit_log; CREATE объектов схемы, DELETE документов и UPDATE аудита запрещены.

Миграции 0001–0005 присутствуют. Preflight под qarzhy_app прошёл, документов 126, денежных движений 35 332. Никакие миграции, восстановления или изменения финансовых данных при переключении не выполнялись.

API перезапущен с удалённой конфигурацией `.env.backend.local`; health вернул HTTP 200. Frontend http://127.0.0.1:3000 отвечает HTTP 200, API — http://127.0.0.1:3139. Параллельный main на порту 3001 продолжает использовать свою SQLite-копию.

Временный `.env.pg-admin.local` удалён после успешного TLS-входа через qarzhy_app и проверки прав. Настройки локальной fin_test сохранены в игнорируемом `data/local-postgres/.env.backend.local.before-remote`.

Для входа в приложение нужны существующие пользователи удалённой fin. Локальный `local.admin` на удалённый сервер не переносился, пароли удалённых пользователей не менялись. Вход пользователя и финансовый обзор после переключения ещё не проверены: в локальном файле начальных реквизитов не найден пароль finance в ожидаемом формате. Это отдельная проверка от успешного подключения роли PostgreSQL.

Туннель должен оставаться открытым. Для возврата к локальной базе: остановить API, восстановить `.env.backend.local` из сохранённой копии и снова выполнить `npm run api:local`.
