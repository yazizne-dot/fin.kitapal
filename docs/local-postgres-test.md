Восстановлен полный архив `data/backups/startup-20261027/fin-full-20261027T094426Z.dump`, затем применены миграции 0003–0005. Все версии 0001–0005 на месте; preflight через ограниченную роль прошёл.

Сохранены 126 документов, 35 332 денежных движения и 12 исходных пользователей. Контрольные суммы полных строк документов и движений совпадают с бэкапом. Добавлен один отдельный пользователь `local.admin`; пароли исходных пользователей не менялись.

При восстановлении пропущена только команда `SET transaction_timeout = 0`, которую добавляет клиент pg_dump 18: этот параметр не поддерживается сервером PostgreSQL 16. Содержимое данных не изменялось. Восстановление выполнено одной транзакцией с остановкой при ошибке.

Проверены в Chrome: вход, загрузка обзора, отсутствие ошибок JavaScript, ответы HTTP 200 для me/data/documents/movements/plans и исторического P&L. Планы проверяются с `organization_id=1`; без организации API обоснованно возвращает 422. Старый журнал сохраняет исходные отметки demo; отдельная кнопка перехода к Kitapal Excel открывает импортированные отчёты PostgreSQL.

## Повторный запуск

Из корня проекта, если PostgreSQL остановлен:

```sh
./data/local-postgres/runtime/Postgres.app/Contents/Versions/16/bin/pg_ctl \
  -D ./data/local-postgres/cluster -l ./data/local-postgres/server.log start
```

В отдельных терминалах:

```sh
npm run api:local
```

```sh
npm run dev
```

Остановить локальную PostgreSQL:

```sh
./data/local-postgres/runtime/Postgres.app/Contents/Versions/16/bin/pg_ctl \
  -D ./data/local-postgres/cluster stop -m fast
```

`.env.backend.local` теперь указывает только на локальную fin_test. Прежние локальные конфигурации сохранены в `data/local-postgres/.env.backend.local.before-local` и `.env.local.before-local`. Настройки основного подключения `.env.pg-backup.local` не менялись. Сертификат и данные локального сервера, пароли и снимки проверки исключены из Git. Временный администраторский файл основной базы для этой настройки не использовался.

**Не задавайте TEST_DATABASE_URL на эту восстановленную копию для автоматических интеграционных тестов:** `npm run test:backend` при наличии переменной удаляет схему qarzhy в fin_test. Для таких тестов нужен ещё один отдельный кластер с пустой одноразовой fin_test на другом порту. Тесты без доступа к базе запускаются через `env -u TEST_DATABASE_URL npm run test:backend`.

Ограничения импортированной истории сохранены: coverage не настроено, начальный баланс не подтверждён. Уязвимости зависимостей из [предыдущего отчёта](local-startup-2026-10-27.md) в этой задаче не исправлялись. Для работы с основной fin всё ещё потребуется отдельно создать роль приложения административным подключением.
