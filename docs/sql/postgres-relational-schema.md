# Новая реляционная схема

Скрипт: [postgres-relational-schema.sql](postgres-relational-schema.sql).
Архитектура: [database-architecture.md](../database-architecture.md).

Создаёт 49 таблиц, первичные и внешние ключи, индексы, ограничения,
триггеры целостности и базовые справочники ролей и разрешений.
Пользователи, пароли и финансовые данные в скрипт не включены.

## Запуск

PostgreSQL 17+. В DBeaver выберите нужную базу и выполните **весь файл как SQL-скрипт**.
Скрипт содержит собственные BEGIN и COMMIT.
Схема `qarzhy` должна отсутствовать: если она уже существует, выполнение завершится
ошибкой без замены существующих таблиц. После ошибки выполните ROLLBACK.
Для проверки можно использовать отдельную пустую базу.
Скрипт не удаляет существующую схему и не подключается к рабочей базе автоматически.

Старые `postgres-data.sql` и `postgres-data-parts/*` несовместимы с новой структурой.
Для переноса подготовлен отдельный [преобразователь и инструкция](postgres-relational-data.md)
в документы, движения, остатки и исторические показатели с проверкой сумм.
Скрипт схемы сам данные не загружает.
`import_batches` хранит историю переноса; новые записи программы получают
`import_batch_id = NULL`.

## Граница реализации

Роли и разрешения здесь представлены данными. Сервер должен проверять доступ,
включая права администратора и финансиста; RLS и роли подключения не настроены.
Создание восьми сотрудников выполняется при настройке пользователей.

Требуются отдельные серверные транзакции проведения документов, утверждения
расходов и их отмены, защиты закрытых периодов, контроля последнего администратора,
обновления ревизии и расчёта отчётов. Уникальный активный финансовый факт по расходу
защищает от повторного включения; перевод статуса сам по себе факт не создаёт.
Поле `financial_events.active` позволяет сохранить отменённое признание расхода.
Автоматический расчёт себестоимости и контроль доступного остатка требуют
отдельной реализации после выбора метода оценки.

## Проверка

Интеграционные проверки выполняют DDL в PostgreSQL WASM (PGlite), затем проверяют
внешние ключи, итоги документов, переводы, частичные оплаты, контекст организаций,
точность сумм, неизменяемость истории и настройки покрытия отчётов.
Это не заменяет проверку на целевом сервере PostgreSQL и конкурентных транзакций.

```sh
PGLITE_MODULE=/absolute/path/node_modules/@electric-sql/pglite/dist/index.js node --test tests/postgres-relational-schema.test.mjs
```
