# Исправления после первоначального импорта

Применяется к уже загруженным данным. Повторно создавать таблицы или выполнять
`postgres-relational-data.sql` не нужно.

## Что исправляется

На основании подтверждений пользователя 20.10.2026:

- Строка Cash Flow 5441: дата 24.01.2023.
- Строки 30520–30522: дата 31.12.2025.
- Шесть пропущенных кассовых остатков становятся подтверждёнными нулями.
- Два текстовых имени в колонке суммы признаны дубликатами ответственного:
  реальные расходные суммы уже были перенесены.
- Два неназванных подытога P&L проверены по всем 12 месяцам: они повторяют
  уже перенесённые строки и не создают дополнительные финансовые факты.

14 замечаний переходят в `resolved`. Семь исторических ограничений — в `accepted`:
неизвестные организации/счета сохраняются без вымышленных связей; товарные
строки авторитетны, исходный расходящийся свод остаётся исторически сообщённым
значением; два вспомогательных листа сохранены как справочные материалы.

Все 21 замечание остаются в журнале, исходное описание сохраняется.
Появляется запись аудита с исходными датами и принятыми решениями.
Суммы денежных движений, количество и стоимость товарных строк не меняются.

Пакет импорта станет `completed`, открытых замечаний — 0. Это завершение
переноса с согласованными ограничениями, а не утверждение рабочего начального
баланса: snapshot остаётся `draft`, правил покрытия отчётов пока нет.

## Как применить

Откройте **`data/postgres-relational-corrections.sql`** в DBeaver и выполните
весь небольшой файл, от BEGIN до COMMIT. Скрипт проверяет fingerprint исходного
пакета, точный набор замечаний и затрагиваемые даты/суммы. При расхождении
ничего не применяет. При ошибке выполните `ROLLBACK;` и сохраните сообщение.

После успеха:

```sql
SELECT status, count(*) FROM qarzhy.import_issues GROUP BY status ORDER BY status;
SELECT count(*) AS open_issues FROM qarzhy.import_issues WHERE status='open';
SELECT status, finished_at FROM qarzhy.import_batches;
SELECT status FROM qarzhy.balance_snapshots;
SELECT count(*) AS confirmed_zero_balances
FROM qarzhy.cash_balances WHERE external_key LIKE 'resolution/zero/%' AND amount=0;
```

Ожидается: 0 открытых, 14 resolved, 723 accepted (включая 716 прежних),
пакет completed, snapshot draft, 6 добавленных нулей.
Повторный запуск пропускается по версии миграции и не дублирует данные.

## Воспроизведение проверки

```sh
python3 scripts/resolve_relational_issues.py
python3 -m unittest discover -s tests -p '*_test.py'
PGLITE_MODULE=/absolute/path/node_modules/@electric-sql/pglite/dist/index.js node scripts/verify_relational_corrections.mjs
```

Генератор не подключается к базе, не меняет исходный экспорт и проверяет
контрольные суммы файлов. Проверка применяет исходный экспорт и исправления
в отдельной PostgreSQL WASM, проверяет откат при конфликте, повторный запуск,
сохранение денежных и товарных сумм. Рабочую базу этот процесс не меняет.
