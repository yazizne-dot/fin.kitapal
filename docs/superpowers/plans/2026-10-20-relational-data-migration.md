# Relational data migration implementation plan

**Goal:** создать SQL данных для новой схемы с сохранением реальных SQLite и Excel.
**Spec:** ../specs/2026-10-20-relational-data-migration-design.md
**Execution:** текущая сессия; рабочую PostgreSQL не менять.

## Ограничения

- Decimal для исходных сумм, стабильные external_key, сессии исключены.
- SQLite legacy_ledger и Excel imported_finance разделены. coverage не угадывать.
- Не присваивать неизвестную организацию, склад, счёт или автора решения.
- Ошибки источника и неопознанные значимые области сохранять в import_issues.
- Не объявлять полный перенос завершённым при открытых проблемах источника.

## Задачи

- [x] Тесты: точные суммы, два направления, пропуск нулей, дата Excel, повторяемые ключи.
- [x] Общий builder: справочники, provenance, диагностика, SQL в транзакции только в пустую новую схему.
- [x] SQLite: пользователи, документы, начисления, оплаты, планы, расходы и аудит.
- [x] Excel: денежные строки, товарный справочник и остатки, кассы, задолженности, основные средства, исторические серии P&L/бюджетов/продаж.
- [x] Отчёт количества и сумм, покрытие листов, сохранение неопределённости вместо вымышленных связей.
- [x] Интеграция: выполнить DDL + данные в PGlite; проверить FK, суммы, повторный запуск и откат.
- [x] Инструкция для DBeaver, отдельный приватный SQL-файл и manifest; проверить diff.

## Результат реализации

16 Python-проверок, 9 проверок DDL и полный импорт в PGlite прошли.
Независимое ревью выявило классификацию годовых процентов и дополнительные
своды по статьям; оба случая исправлены с регрессионными тестами.
Все 954 операции представлены; 30 планов, 12 пользователей и 4 согласованных
расхода сохранены. Суммы денежных строк сверены точно.

Нерешённые вопросы источника: 21, перечислены в приватном отчёте импорта.
Не считать завершёнными сверку исходного баланса, настройку coverage,
классификацию двух строк без названий и вспомогательных областей.
Рабочая база не изменялась; импорт выполняет пользователь в DBeaver.

## Риски для проверки

Две суммы прихода/расхода в строке; отрицательные значения; даты против года/месяца;
одинаковые SKU при разных названиях; пропущенные суммы и Excel #REF!;
неизвестный проверяющий расходов; пересечение контрольных сводов с первичными данными.
