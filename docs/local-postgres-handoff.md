# Передача базы разработчику

Доступ к ветке осуществляется через доступ к репозиторию. Write-доступ обычного
соавтора не ограничен одной веткой; разработчик работает в `feat/postgres-migration`.
Приглашение отправляет владелец в Settings → Collaborators → Add people.
Для приглашения указан адрес `kaisariskak@gmail.com`.

## Создание дампа текущей базы

Заполните локальный игнорируемый файл `.env.pg-backup.local`: `PGUSER` и
`PGPASSWORD` из подключения DBeaver fin. Пробелы вокруг значений убираются;
если они являются частью пароля, заключите значение в кавычки. Подстановки
переменных и shell-код не выполняются. Параметры по умолчанию:
127.0.0.1:15433, база fin. Убедитесь, что это нужное текущее подключение.

```sh
python3 scripts/backup_postgres.py
```

Результат — `data/backups/qarzhy-*.dump` и SHA-256 manifest. Скрипт не изменяет
базу. В дамп входит схема qarzhy и её данные, кроме сессий входа. Роли сервера,
права владельца и другие схемы не экспортируются. Дамп содержит финансовую
информацию и хеши пользовательских паролей; передавайте его разработчику
отдельно по согласованному приватному каналу. В Git он не включается.

## Локальное восстановление

Нужен установленный и запущенный Docker с Compose. Клонируйте репозиторий
и переключитесь на `feat/postgres-migration`, затем запустите:

```sh
docker compose -f compose.dev-db.yml up -d --wait
docker compose -f compose.dev-db.yml exec -T postgres pg_restore --no-owner --no-acl --single-transaction --exit-on-error -U qarzhy_dev -d fin < /absolute/path/qarzhy-backup.dump
docker compose -f compose.dev-db.yml exec -T postgres psql -U qarzhy_dev -d fin -c "SELECT count(*) FROM qarzhy.cash_movements;"
```

Восстанавливайте в пустую локальную базу, не запускайте предварительно SQL
создания таблиц. Повторное восстановление в ту же схему завершится ошибкой.
Указанный файл дампа нужно заменить его реальным именем.

Локальный контейнер использует PostgreSQL 18, чтобы pg_restore соответствовал
версии создавшего архив pg_dump 18. Рабочая база не обновляется (при проверке
источника 20.10.2026 сервер сообщил PostgreSQL 16.15). Формат архива и инструкция
для локального восстановления не утверждают совпадение версий dev/production.

Подключение DBeaver: host 127.0.0.1, port 15434, database fin,
user qarzhy_dev, password local_dev_only. Эти реквизиты только для локального
контейнера, доступного с этого компьютера.

На дату передачи ожидаются 12 users, 126 documents, 30 payment_plans,
35332 cash_movements, 0 открытых import_issues и completed import_batches.
Текущий snapshot остаётся draft. Если после передачи база менялась,
сверяйте количества с источником на дату дампа.

Дамп PostgreSQL содержит уже применённые исправления. Первоначальные SQL-файлы
импорта не заменяют дамп текущей базы. Восстановление БД само по себе пока
не переключает существующее приложение с прежнего хранилища на PostgreSQL.
