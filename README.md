# Qarzhy — Kitapal қаржылық порталы

## Новый PostgreSQL API (этап разработки)

В каталоге [`backend/`](backend/) находится отдельный Node.js API для схемы `fin.qarzhy`. Реализованы авторизация с обязательной сменой пароля каждые 30 дней, финансовые записи, P&L, денежные потоки, правила покрытия и редактор отдельных отчётных чисел с пересчётом прибыли. Next.js содержит прокси к отдельному API, который включается через `API_INTERNAL_URL`, но обычный интерфейс пока остаётся на прежнем маршруте до переноса баланса, остальных отчётов, импорта, экспорта и общего `/api/data`. Запуск нового API не изменяет схему базы и не загружает дамп.

Для локального запуска задайте `DATABASE_URL` (роль приложения), `PUBLIC_APP_ORIGIN` (например, `http://127.0.0.1:3000`), `CSRF_SECRET` (случайное значение длиной не менее 32 байт) и при необходимости `API_PORT` (по умолчанию 3139). Затем запустите `npm run api:dev`. Миграции `0003` и `0004` запускаются **отдельно** с `MIGRATION_DATABASE_URL`: сначала `npm run db:migrate -- --check`, после проверки цели — `npm run db:migrate -- --apply`. Не применяйте их к заполненной рабочей базе и не включайте `API_INTERNAL_URL`, пока не завершена проверка всех экранов. Никогда не используйте рабочую базу для `npm run test:backend`.

Для тестов поднимите отдельную PostgreSQL 18 базу `fin_test` на порту 15435 (`compose.test-db.yml` либо локальный кластер), задайте `TEST_DATABASE_URL` и запустите `npm run test:backend`. Скрипт удаляет и пересоздаёт только схему `qarzhy` в базе с именем ровно `fin_test`. Контракт маршрутов и сведения о миграции: [docs/api/postgres-endpoints.md](docs/api/postgres-endpoints.md).

## Next.js нұсқасы (`тест` веткасы)

Қолданба **Next.js 16.3.7 + React 19.3.0 + TypeScript** арқылы іске қосылады. Node.js **24+** қажет.

```sh
npm ci
npm run dev
```

Ашу: http://127.0.0.1:3000. Production режимі:

```sh
npm run build
npm start
```

- `app/` — Next.js App Router, layout, API route және серверлік модульді алғашқы API сұрауында іске қосу.
- `components/`, `features/` — толық React/TypeScript интерфейсі: есептер, басқару беттері, жеке кабинет, сүзгілер және URL маршруттары.
- `server/` — SQLite, қаржы есептеулері, API және экспорт модульдері; `server/http/web-handler.mjs` Next.js сұрау/жауап форматына бейімдейді.
- `tests/helpers/api-server.mjs` — тек оқшауланған API тесттерінің көмекші сервері. Қолданбаны онымен іске қоспаңыз.

SQLite базасы, пайдаланушылар, бастапқы Excel/JSON деректері және есептеу логикасы сақталған. `next build` базаны ашпайды және миграция жасамайды. Қаржылық деректер `data/` ішінде runtime кезінде оқылады, build пакетіне қосылмайды. Орналастырғанда осы каталог пен SQLite үшін тұрақты, жазуға болатын диск қажет; бұл конфигурация Node.js серверіне арналған. API жауаптары кэштелмейді; беттерде әр сұрауға жеке CSP nonce қолданылады.

Тексеру:

```sh
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:next
```

Chrome орнатылған болса, соңғы екі команданың орнына `PLAYWRIGHT_CHANNEL=chrome npm run test:next` қолдануға болады. Тесттер уақытша SQLite базаларымен жұмыс істейді: API тесттері 3137/3138, Next production тесті 3140 портын қолданады (`NEXT_TEST_PORT` арқылы өзгертіледі). Нақты `data/portal.sqlite` тексеруде пайдаланылмайды.

Көшіруден кейін **45 серверлік регрессиялық, 10 React компоненттік және 7 Next.js интеграциялық тест** өтті; TypeScript пен production build сәтті. Chrome автоматты тексеруі кіруді, есептерді, басқару беттерін, модаль терезені, тіл ауыстыруды, шығуды және қызметкер кабинетін қамтиды.


## Админка және жеке кабинеттер

Админ (`admin`) мен қаржыгер (`finance`) есептерді және пайдаланушыларды басқарады: кабинет қосу/бұғаттау, логин мен уақытша пароль беру, шығындарды қарау, есеп сандарын түзету, жаңа ақпарат енгізу. Өз логині мен паролі «Жеке кабинетте» өзгереді. Соңғы белсенді админді бұғаттауға болмайды.

Қызметкерлер тек өзінің шығындарын енгізеді, түзетеді және өзінің паролі мен тілін ауыстырады. Компания есептері, басқа қызметкерлердің шығындары, басқару және экспорт API-лары оларға жабық. Қазақша/Русский ауыстырғышы әр панельде бар; таңдау профильде сақталады. Файлдағы бап атаулары және пайдаланушы мәтіні түпнұсқа тілінде сақталады.

| Кабинет | Логин |
| --- | --- |
| Бухгалтер | buhgalter |
| Маркетолог | marketolog |
| РОП | rop |
| Логистик | logist |
| Курьер | kurier |
| Зав склад | sklad |
| Атырау филиал | atyrau |
| Сату менеджер | sales |

Қолданыстағы базада админ мен қаржыгер бұрынғы паролін сақтайды (`demo2026`, егер бұрын өзгертілмеген болса). Қызметкерлерге кездейсоқ уақытша парольдер жасалады: `data/portal.sqlite.initial-access.txt` (0600; веб арқылы таратылмайды). Алғашқы кіруде пароль ауыстыру міндетті. Кейін «Пайдаланушыларды басқару → Жаңа пароль беру» арқылы қалпына келтіріледі. Парольді қайта беру бұрынғы сессияларды жабады. Ескі бухгалтер/менеджер демо кабинеттері бұғатталған; тарихи жазбалары сақталған.

Қызметкер шығыны алдымен «Қаралуда» болады. Админ/қаржыгер «Есепке қосу» арқылы оны P&L операциялық шығысына және ДДС-ке бір рет қосады. «Қайтару» оны есептен алып, қызметкерге түзетуге мүмкіндік береді. Excel ішінде бұрын есептелген шығынды қайта мақұлдамаңыз.

«Есеп сандарын түзету»: файл → парақ → ұяшық/бап іздеу → «Өзгерту». Себебі міндетті. Бастапқы Excel өзгермейді, түзету жеке сақталады және бастапқыға қайтарылады. Қатар өзгерткенде нұсқасы тексеріледі. P&L-дің негізгі қорытындылары және баланстың негізгі баптары қайта есептеледі. Бұл толық Excel формула қозғалтқышы емес: күрделі формулалар мен сыртқы сілтемелер орындалмайды; тиісті қорытынды ұяшығын бөлек түзетуге болады. Қайта импортта файл SHA-256 өзгерсе, ескі түзетулер жаңа файлға автоматты қолданылмайды.

«Жаңа ақпарат»: кіріс/шығыс қосу, сомасын түзету, есептен алу. ДДС-ке қосу бөлек белгіленеді. Баланс — 01.09.2026 сәтіндегі жеке қалдық; жаңа операция оны автоматты өзгертпейді. Жаңа жазбалар сату арналарына автоматты бөлінбейді.

Автор, уақыт, себеп, бұрынғы/жаңа мән журналда сақталады. Парольдер журналға жазылмайды. Миграция алдындағы көшірме: `data/portal-before-accounts.sqlite`. Автоматты тексеру: `npm test` және `npm run test:next`.

## Ағымдағы нұсқа: берілген Excel деректері

Админ және қаржыгер кіргенде `P&L + Бюджетирование - 08 ай.xlsx` деректері ашылады. Әдепкі кезең — **2026-08**. 2023–2025 толық жылдары және 2026 қаңтар–тамыз фактісі бар (44 ай). Файлда 2026 қыркүйек–желтоқсан — тек жоспар. «Жыл басынан» режимі және нақты сату арналары қосылған.

- P&L, сату арналары, шығыс бюджеті, есеп баптары, дереккөз және арифметикалық тексерулер.
- Әр санның парағы, ұяшығы және бар болғанда формуласы сақталады. Ортақ Excel формуласының бастапқы ұяшығы бөлек көрсетіледі.
- Негізгі сандар — файлдың сақталған мәндері. Формулалар сыртқы жүйелерден қайта есептелмейді.
- Толық қолжетімді жыл басынан кезеңде P&L-дің **O / Тотал** бағаны қолданылады. Қысқа аралықта айлық мәндер қосылады. Өткен жыл дәл сол айлармен салыстырылады.
- «Баптардан қайта есеп» — бөлек арифметикалық бақылау. Файлдағы қорытынды үнсіз өзгертілмейді.
- Сомалар тиын дәлдігімен көрсетіледі, теріс мәндер мен 0,1 бюджет жазбалары сақталады. Бос ұяшық пен нөл бөлек көрсетіледі.
- Арна бойынша тек түсім, өзіндік құн және жалпы пайда көрсетіледі. Ортақ шығыстар арналарға ойдан бөлінбейді.
- Баланс және ДДС екі қосымша файлдан жүктелген (төмендегі бөлім). Дебиторлық берешек құжаттарының тізілімі және бастапқы ақша қалдығы әлі қажет.
- Excel мәндері «Есеп сандарын түзету» арқылы өзгереді. Бұрынғы демо операциялары бөлек режимде сақталған: «Баптаулар → Демо режимін ашу».
- Қызметкерлерге жалпы компанияның Excel деректері берілмейді.

### Дереккөзді қайта шығару

Бастапқы Excel өзгертілмейді. Тек ZIP ішіндегі кесте ұяшықтары оқылады; көлемді pivot cache жазбалары импортталмайды. Сондықтан бұл толық бастапқы операциялар импорты емес.

```sh
python3 scripts/read_workbook.py '/path/to/P&L + Бюджетирование - 08 ай.xlsx' data/workbook-source.json
npm start
```

Сервер жұмыс істеп тұрса, қайта іске қосыңыз. Қазіргі импорттау моделі осы файлдың 2023–2026 P&L және бюджет құрылымына арналған; басқа құрылымды файлды пайдаланар алдында баптар мен кезеңдер сәйкестігін тексеру қажет. `data/workbook-source.json` — жеке қаржылық деректер, `.gitignore` ішіне қосылған және веб арқылы тікелей таратылмайды. `WORKBOOK_PATH=disabled` арқылы Excel режимін өшіруге болады.

Бастапқы workbook тесттері `npm test` құрамында. Оның ішінде нақты мәндер, O бағаны/айлық қорытынды айырмасы, арна сүзгісі, бос/теріс мәндер, болашақ жоспарды фактпен араластырмау, менеджер құқығы және барлық беттердің құрастырылуы тексерілген.

Техникалық тапсырма бойынша жасалған жұмыс істейтін жергілікті MVP: қазақ тіліндегі бейімделетін интерфейс, Node.js сервері және SQLite дерекқоры. Бұл басқарушылық есеп; реттелетін бухгалтерлік немесе салық есептілігін алмастырмайды.

## Іске қосу

Node.js 24 немесе жаңарақ нұсқасы қажет.

```sh
npm ci
npm run build
npm start
```

Ашу: http://localhost:3000

Әзірлеу режимі: `npm run dev` (Next.js Fast Refresh).

Алғашқы іске қосу кезінде `data/portal.sqlite` файлы жасалып, 2025 жылғы қаңтар – 2026 жылғы қыркүйек аралығындағы демонстрациялық операциялар енгізіледі. Бастапқы таңдалған ай — 2026-09. Қазан айына ДДС жоспары бар. Интерфейсте деректердің демонстрациялық екені көрсетілген.

Кіру логин және пароль арқылы орындалады. Қолданыстағы базаға арналған кабинеттер жоғарыдағы бөлімде көрсетілген. `PORTAL_PASSWORD` тек жаңа базаның бастапқы админ/қаржыгер пароліне әсер етеді.

## Іске асырылған мүмкіндіктер

- Қаржылық шолу: ақша, түсім, жалпы/таза пайда, дебитор/кредитор, шығыс құрылымы, ұйымдар және 30 күндік ақша болжамы.
- Кезең мен ұйым сүзгілері, ай/тоқсан диаграммасы, операциялардан іздеу.
- ОПиУ: факт, енгізілген бюджет, ауытқу теңге/пайызбен, өткен жылдың осы айы, жылдық өзгеріс. Нөлге бөлгенде «—». Туынды бюджет көрсеткіштері негізгі баптар толық енгізілгенде есептеледі.
- Баланс: бастапқы қалдық, кезең қозғалысы, соңғы қалдық және теңдік бақылауы. Пайда капиталда бір рет есептеледі.
- ДДС: түсімдер, төлемдер, операциялық/инвестициялық/қаржылық қызмет; ішкі аударымдар қосылмайды. Соңғы ақша баланспен салыстырылады.
- Контрагент, бастапқы құжат және мерзім бойынша дебитор/кредитор берешегі. Құжат нөмірі төлемді бастапқы операциямен байланыстырады.
- Қаржыгер болашақ ақша оқиғаларын қосады; күнделікті 30 күндік қалдық пен ықтимал касса алшақтығы есептеледі. Жоспар фактіге әсер етпейді.
- Операцияларды қолмен енгізу, соманы/өзіндік құнды себеппен түзету және есептерді қайта есептеу.
- CSV импорт: UTF-8, үтір/нүктелі үтір, 2 MB, 5000 жол. Қайталану кілті — `source + external_id`. Жарамсыз жолдар журналға жазылады, жарамды жолдар сақталады.
- Нақты `.xlsx` Excel экспорты: ОПиУ, баланс, ДДС, берешек, жоспар, журнал, операциялар. Ұяшық мәтіні формула ретінде орындалмайды.
- Кезеңді жабу; себеппен қайта ашу; ескі/жаңа сомалармен өзгеріс журналы.
- Сервердегі рұқсат тексерулері, scrypt пароль хэштері, HttpOnly/SameSite cookie, 24 сағаттық сессия, кіруге шектеу және сыртқы origin-нен өзгерту сұрауларын қабылдамау.

## CSV үлгісі

Үлгі интерфейстің «Деректерді жүктеу» бөлімінде бар.

```csv
external_id,source,date,org,point,counterparty,document,kind,amount,cost,due,article
sale-001,my-system,2026-09-28,Qalam Books,Алматы,Клиент,SALE-001,sale,150000,75000,2026-10-10,Кітап сату
payment-001,my-system,2026-09-29,Qalam Books,Алматы,Клиент,SALE-001,receipt,100000,0,,Клиент төлемі
```

`amount` және `cost` — бүтін теңге. `cost` сатудың/қайтарымның өзіндік құнын білдіреді. Сатылым мен төлемнің контрагенті, ұйымы және құжат нөмірі бірдей болуы керек. `due` — бастапқы құжаттың төлем мерзімі.

Операциялар: `sale`, `return`, `receipt`, `purchase`, `supplier_payment`, `expense`, `expense_payment`, `depreciation`, `tax`, `tax_payment`, `capital`, `loan`, `loan_payment`, `asset`, `transfer`.

Салық мөлшерлемесі кодта бекітілмеген: `tax` операциясына бухгалтерия бекіткен соманы енгізеді. Шығыс есептеу (`expense`) және шығысты төлеу (`expense_payment`) — екі бөлек оқиға.

Қайталанған импорт бұрынғы жазбаны өзгертпейді. Түзету үшін операция сомасының жанындағы батырманы пайдаланыңыз: себеп және бұрынғы/жаңа мән журналда сақталады.

## Нақты пайдалануға дейінгі шектеулер және келісімдер

ТЗ толық өндірістік енгізуді талап етеді. Бұл нұсқада төмендегілер әлі іске асырылмаған немесе нақты деректермен келісуді қажет етеді:

1. 1С/банк/касса API интеграциясы және автоматты синхрондау: қазір қолмен CSV импорт бар.
2. Ұйым/бренд/нүкте/пайдаланушы анықтамалықтарын басқару: үш демонстрациялық ұйым мен төрт пайдаланушы кодта берілген. Көп пайдаланушыға жеке пароль орнату және тіркелгі басқаруы қажет.
3. Бастапқы қалдықтарға арналған арнайы құжат, аванстар, шоттар/валюталар және валюталық қайта бағалау. Қазір тек KZT, базалық актив/міндеттеме түрлері бар.
4. SKU, сан, баға, жеңілдік, қойма қозғалысы, қордың өзіндік құнын автоматты есептеу, тауар/тираж бойынша аналитика. Қазір дайын сатылым сомасы және өзіндік құн импортталады.
5. Топішілік сатуды анықтау және консолидацияда алып тастау. Демода топішілік сатулар жоқ. «Барлық ұйымдар» — бекітілген консолидация емес, ұйымдардың қосындысы.
6. Дистрибьютор лимиттері, апталық ДДС, бар жоспарды өзгерту/жою, шығындарды жобаларға бөлу, есептелген төлем мерзімдерінен автоматты болжам. Қазір ДДС жоспарына оқиғалар қолмен қосылады, берешек болжамға автоматты көшірілмейді.
7. Жылдық толық есеп, пайдаланушы таңдайтын еркін аралық, бренд/контрагент бойынша жалпы сүзгі. Қазір айлық есеп, өткен жыл салыстыруы және тоғыз айлық динамика бар.
8. HTTPS, SSO/парольді қалпына келтіру, серверлік резервтік көшіру мен қалпына келтіру, өндірістік орналастыру.
9. Сомалар бүтін теңгемен сақталады. Тиын дәлдігі қажет болса, сақтау мен импорт ережелерін келісу керек.

Бастапқы ТЗ: `docs/technical-specification.txt`. Өндірістік деректерді демонстрациялық дерекқорға қоспаңыз.

Демосыз бөлек базаға іске қосу мысалы (жаңа файл жолын пайдаланыңыз, парольді өзіңіз орнатыңыз):

```sh
DEMO_DATA=0 DB_PATH=data/live.sqlite PORTAL_PASSWORD='CHANGE-THIS-BEFORE-USE' npm start
```

`PORTAL_PASSWORD` тек базаға пайдаланушылар алғаш жасалғанда қолданылады. Ол бар пайдаланушы паролін өзгертпейді. Қазіргі төрт рөл үшін бір бастапқы пароль пайдаланылады; бұл өндірістік тіркелгі басқару жүйесі емес. Сервер әдейі 127.0.0.1 адресін ғана тыңдайды.

Резервтік көшірудің ең қарапайым жергілікті тәсілі: серверді тоқтатып, SQLite базасын көшіріңіз. Жұмыс істеп тұрған WAL базасының тек негізгі файлын көшіруге болмайды. Өндірістік автоматты резерв және қалпына келтіру тесті жеке бапталуы керек.

## Тексеру

```sh
npm test
```

Тесттер уақытша SQLite базасы және 3137 портында оқшауланған серверді пайдаланады; негізгі демо база өзгермейді. Бастапқы режим тесттері: бухгалтерлік теңдіктер, төлемді қосарлап есептемеу, салық/аударым ережелері, авторизация, импорт дубликаттары мен қателер, жабық кезең, түзету аудиті, бюджет, жоспардың фактіге әсер етпеуі және Excel форматы.

Next.js интерфейсі Chrome автоматты браузер тестімен тексерілді; іске қосу командалары жоғарыда.

Кіру бетінде «Құпиясөзді көрсету» енгізілген парольді көрсетеді/жасырады. «Мені есте сақтау (30 күн)» сервер сессиясын 30 күн сақтайды; белгіленбесе браузерлік session-cookie және серверде ең көбі 24 сағат қолданылады. Пароль браузердің localStorage қоймасына жазылмайды. «Жүйеден шығу» сақталған сессияны жояды.
